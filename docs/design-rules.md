# デザインルール（KANZAKI Portfolio）

> このサイト専用のデザインルール。原典は [DESIGN-apple.md](DESIGN-apple.md)（Appleサイト分析）だが、

> 本プロジェクトの規約（`coding-rules.md`：8px系トークン・`rem()`・oklch）と和文組版に翻訳済み。

## コンセプト

**ミニマム・フラット・青一色。** 余白と面の色替えだけで階層を作り、装飾は足さない。
読者（採用担当者・依頼主）が数秒で要点を掴めることを、すべての装飾判断より優先する。

- グラデーション・ボーダー装飾は原則禁止。区切りは「面の色の切り替え」と「余白」で作る。影はカード状の面だけ、ごく淡い落ち影を許容（浮きは面の色差＋影の二段構え）。それ以外はフラット
- アクセントカラーは青1色。「押せるもの」だけが青い
- 1セクション＝1メッセージ

## カラートークン

`oklch()` で定義する（`scss/foundation/_base.scss`）。**ライトテーマ固定**（ダークモードはポートフォリオには過剰と判断し廃止。2026-07）。hexは由来メモであり、実装には書かない。

| トークン | 値 | 用途 |
|---|---|---|
| `--color-primary` | `oklch(52.2% 0.177 255.8)` (#0066cc) | リンク・CTA・アクション全般。**唯一のアクセント** |
| `--color-primary-focus` | `oklch(56.3% 0.193 256.2)` (#0071e3) | フォーカスリング（`outline: 2px solid`） |
| `--color-on-primary` | `oklch(100% 0 0)` | 青ボタン上のテキスト |
| `--color-canvas` | `oklch(100% 0 0)` (#ffffff) | 基本の背景 |
| `--color-canvas-alt` | `oklch(97.1% 0.003 286.4)` (#f5f5f7) | 交互セクション・フッターの背景 |
| `--color-ink` | `oklch(23.2% 0.004 286.1)` (#1d1d1f) | 見出し・本文。純黒は使わない |
| `--color-ink-muted` | `oklch(54.0% 0.008 286.1)` (#6e6e73) | 補足・キャプション・メタ情報 |
| `--color-hairline` | `oklch(90.7% 0 0)` (#e0e0e0) | カードの1pxヘアライン（使用は最小限） |

### ルール

- **青は「押せるもの」専用。** リンク・ボタン・フォーカス以外（見出しの飾り・アイコン装飾・背景）に青を使わない。青の価値は希少性で決まる
- 第2のアクセントカラーを作らない。強調が必要なら面の色替え（canvas ↔ canvas-alt ↔ ink面）か余白で解決する

## タイポグラフィ

### フォントスタック

```scss
// 見出し・本文共通（和文優先のシステムスタック＋Roboto）
font-family: Roboto, "Hiragino Sans", "Noto Sans JP", system-ui, sans-serif;
```

- SF Proは使えないため、欧文は **Roboto**（バリアブル wght 100-900・SIL OFL 1.1・セルフホスト、ライセンス全文は fonts/LICENSE-Roboto.txt）、和文はシステムフォント優先
- ウェイトの梯子は **300 / 400 / 600 / 700**。**500は使わない**（原典のルールを踏襲）。見出しは600、本文は400

### 見出しの階層と行長

- トップの h2 はセクション見出し（`c-section-title`・40px）の6つだけ。Service 配下の Pricing / Flow / FAQ は **h3**（`p-top-service__sub-title`・28px）で、その中の見出しは h4。ヘッダーナビは h2 のセクションまで（Pricing はナビに出さない）
- 読ませる本文の行長は **和文40字まで**：16px の段落は `max-width: rem(640)`、14px は `rem(560)`（profile / works lead / note / service sub-lead / contact で共通）
- 見出しは本文16pxより小さくしない（ラベル的な h3 は 16px＋uppercase＋muted で佇まいを作る）

### スケール（rem() 関数で指定。clampでレスポンシブ）

| トークン | サイズ | weight | line-height | letter-spacing | 用途 |
|---|---|---|---|---|---|
| `--text-hero` | `clamp(rem(34), 5vw, rem(56))` | 600 | 1.15 | `-0.01em`（欧文）/ `0`（和文） | トップのヒーロー見出し |
| `--text-display` | `clamp(rem(28), 4vw, rem(40))` | 600 | 1.25 | 同上 | セクション見出し（h2） |
| `--text-title` | `rem(24)` | 600 | 1.4 | 0 | カード見出し・h3 |
| `--text-lead` | `rem(20)` | 400 | 1.6 | 0 | リード文 |
| `--text-body` | `rem(16)` | 400 | **1.8** | 0 | 本文 |
| `--text-caption` | `rem(14)` | 400 | 1.6 | 0 | 補足・タグ・メタ情報 |
| `--text-fine` | `rem(12)` | 400 | 1.5 | 0 | コピーライト等 |

### 和文組版の翻訳ルール（原典との差分）

- **本文の line-height は 1.8**。原典の1.47は欧文向けで、和文には狭すぎる
- **マイナス字間（Apple tight）は欧文見出しのみ。** 和文見出しは `0`（詰めたい場合も `text-spacing-trim` に任せる。kiso.cssが適用済み）
- 本文サイズは `rem(16)`。原典の17pxは採用しない（8px系・rem基準との整合を優先）
- 見出しの改行位置は `<br>` ではなく幅制御（`max-inline-size` + `text-wrap: balance`）で整える

## 余白・レイアウト

`coding-rules.md` の8px系トークンをそのまま使う。原典のpx値は下表の通り読み替える。

| 原典（Apple） | 本プロジェクト |
|---|---|
| セクション縦 80px | `var(--space-section)`（clamp 64〜120px） |
| カード内 24px | `var(--space-24)` |
| 17px | `var(--space-16)` |
| ボタン 11px×22px | `var(--space-12) var(--space-24)` |

- セクションは **canvas ↔ canvas-alt の交互リズム**で区切る。`<hr>` や装飾ボーダーは使わない
- コンテンツ最大幅：テキスト主体 `rem(720)`、カードグリッド `rem(1080)`（`l-container` で管理）
- グリッドは `gap: var(--space-24)`〜`var(--space-32)`。works カードは 3列 → 2列（タブレット）→ 1列（モバイル）

## 角丸・影・区切り

### 角丸の文法（3種のみ。混ぜない）

| 値 | 用途 |
|---|---|
| `9999px`（ピル） | ボタン・タグ ＝「押せるもの・ラベル」 |
| `rem(16)` | カード（スキル・Service 等） |
| `rem(24)` / `rem(12)` | 作品カード（額装型）の外形／内側の画像上2隅。マット12pxを挟んだ同心の角丸で、単独では使わない |
| `0` | セクション・画像の全幅表示 |

### 影

- **UIは原則フラット。** ボタン・ナビ・タグ・見出しに影は付けない
- **カード状の面だけ例外**：浮きは背景色差（canvas上のcanvas-altカード、またはその逆）を土台に、その上へ**ごく淡い単一の落ち影**（`--shadow-card`）を薄く重ねてわずかに持ち上げる。操作可能なカードはホバーで `--shadow-card-hover` に軽く持ち上げる。対象は works カード・スキルカード・作品詳細のカード状パネル（case / cta / 前後ナビ / 制作物画像）。ニューモーフィズム的な二重影は使わない
- **作品カード（Works）は額装型**：12pxのマットを取った白面に 24px の同心角丸（画像12px＋マット12px。2026-10-14に32/20から縮小）、影は `--shadow-card-soft`（広く薄い2層）。画像は上2隅のみ角丸で下端を白地へフェードさせ、スクショ影は付けない。分類・実案件はピル（`--color-primary-tint` / `--color-accent-mist`）、罫線の下に担当範囲＋詳細リンクのメタ行。参考: 島Navi 記事カード（2026-09-04）
- **作品スクリーンショット**：面の上に置かれるときの強い影 `--shadow-screenshot`（`3px 5px 30px oklch(0% 0 0 / 0.22)`）。カードの淡い影とは別物

### マイクロインタラクション

- ボタン・カードの押下は `transform: scale(0.95)` ＋ `transition: transform 0.2s` で統一
- ホバーで色相を変えない。透明度か下線で応答する
- `prefers-reduced-motion: reduce` を尊重する

## コンポーネント指針

- **ヘッダー（l-header）**：高さ `rem(48)` 前後の細いバー。背景は canvas ＋ `backdrop-filter: blur()`（スクロール追従する場合）。ロゴ＋ナビリンク＋ダークモードトグルのみ。ナビに背景色やボーダーを足さない
- **ヒーロー（p-top-hero）**：`--text-hero` の見出し＋1行のリード＋CTA（青ピル1つ、あってもセカンダリのゴーストピル1つまで）。要素はこの3つで完結させる
- **ボタン（c-button）**：primary＝青地×白文字のピル。secondary＝透明地×青文字×1px青ボーダーのゴーストピル。この2種以外作らない
- **works カード（c-card）**：スクリーンショット（16:10・`rem(8)` 角丸）＋作品名（`--text-title`）＋担当範囲・工夫の2点＋詳細リンク。**「担当範囲・工夫」は必須**（CLAUDE.mdのコンテンツ方針）
- **タグ（c-tag）**：`--text-caption`・ピル・canvas-alt地。技術スタック表示用。青は使わない（押せないため）
- **フッター（l-footer）**：canvas-alt地。リンク列＋コピーライトのみの薄い構成

## Do / Don't

### Do
- 迷ったら要素を削る。ミニマムはこのサイトの機能要件
- 強調したいとき：まず余白を増やす → 次に面の色を替える → 最後にサイズを上げる。色を足すのは解でない

### Don't
- 青以外のアクセントカラーを足さない（成功/エラー等のシステム色が必要になった場合のみ例外を検討し、このファイルに追記する）
- ボタン・タグ・テキスト・ナビに影を付けない（影はカード状の面の淡い落ち影と作品スクショのみ）
- 装飾目的のグラデーション・ボーダー・アイコンを足さない
- 和文見出しにマイナス字間をかけない
- 8px系から外れた余白（10/14/18px等）を使わない
